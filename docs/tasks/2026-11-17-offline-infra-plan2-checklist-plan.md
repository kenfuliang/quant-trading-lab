# Readiness checklist, artifact catalog, conventions and workflow (Plan 2) implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scored, evidence-linked readiness checklist and an artifact catalog, both as JSON registries with generated docs that `make check` keeps fresh, plus a Readiness dashboard tab, a conventions document and the development-workflow rules for a multi-plan build.

**Architecture:** Each catalog is a JSON registry under `research/registry/` with a pure loader and renderer in `research/control/`. A command in `scripts/` does `render|check|build`, following `scripts/stages.py` and `research/control/incumbents.py`. Generated Markdown is checked by string comparison in `make check`. The HTML page is written to `.local/progress/` like the Pipeline tab.

**Tech Stack:** Python 3.12 standard library, `unittest`, Make. No new dependencies.

**Spec:** [offline research infrastructure design](2026-11-17-offline-research-infra-design.md) and the approved master plan of 2026-11-17 (Plan 2 block), reproduced in "Decisions" below.

## Global Constraints

- **Registries:**
  - JSON is hand-maintained.
  - Loaders validate the shape and every evidence path, and reject unknown references.
  - Renderers are pure and deterministic: no clock, sorted output.
- **Generated documents:**
  - They carry the frontmatter `status`, `updated`, `owner`.
  - `updated` comes from the registry's own `assessed` / `updated` field, never from the clock.
  - They contain the line `<!-- Generated by scripts/<name>.py render. Do not edit by hand. -->`.
  - Table cells are escaped with the same rules as `research/control/incumbents.py` `_cell`.
- **Readiness rubric (exact):**
  - Scores: 0 absent, 1 ad hoc or one-off, 2 partial, 3 works for the current scope, 4 robust and tested, 5 production-grade.
  - Scores are in half steps from 0 to 5.
  - Importance is `H`, `M` or `L`; for the weighted average, H = 3, M = 2, L = 1.
- **Fix-first list:** importance `H` and score ≤ 2, sorted by score and then id.
- **Scope:** do not edit files pinned in `research/compatibility.json`. Documentation follows `docs/README.md`. Offline only.

## Decisions (from the approved master plan, binding)

- **Readiness checklist:**
  - Stored as `research/registry/readiness.json`, schema `readiness/v1`.
  - Each entry is `{id, area, aspect, score, importance, evidence, critique, next_action, gates, roadmap_step}`. `gates` lists ids from `research/registry/gates.json`; `roadmap_step` is an integer or null.
  - The header holds `assessed` (a date) and the rubric.
- **Artifact catalog:**
  - Stored as `research/registry/artifacts.json`, schema `artifacts/v1`.
  - Each entry is `{schema_id, name, stage, location, authority, producer, consumers, retention, status}`, with:
    - `stage` ∈ intake, design, data, run, confirm, diagnose, validate, decide, paper, views;
    - `location` ∈ tracked, local;
    - `authority` ∈ authoritative, view;
    - `status` ∈ implemented, planned, template-only, frozen-study-specific.
  - `schema_id` is null for template-only artifacts.
- **Schema scan:** a test scans `research/`, `scripts/`, `paper_trading/` and `reporting/` for `SCHEMA = "…/vN"` or `SCHEMA = '…/vN'`, and for `"schema": "…/vN"` literals in `.py` files. It fails on any id not in the catalog.
- **Cash:** earns zero, and this is disclosed. Strategies are long-only; evaluation is pre-tax (see `docs/goals.md`).

## Review Focus

1. A readiness or catalog entry whose evidence path does not exist must fail `make check`, not render a dead link.
2. A generated doc that is edited by hand, or that went stale after a registry edit, must fail the corresponding `check` with a message naming the file.
3. A new `SCHEMA = "x/v1"` added anywhere in code without a catalog entry must fail the scan test, naming the file and id.
4. Markup, pipes or line breaks in critique or next-action text must not break the Markdown table or inject HTML into the dashboard page.
5. `make check` run from a worktree with no local `.venv` must still find the main checkout's interpreter.
